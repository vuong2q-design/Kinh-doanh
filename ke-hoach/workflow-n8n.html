Bộ workflow n8n

Sáu workflow vẽ đúng dạng node-graph của n8n — mỗi ô là một node với tên node n8n cụ thể ở dòng cuối. Đây là phương án "nhìn luồng bằng sơ đồ" của trục tự động hóa (thay cho script thuần); chọn một trong hai, không chạy song song.

⚡ Node khởi phát (trigger) Chạy tự động 👤 Điểm chờ người duyệt

WF-1 · Đơn hàng mới → giao hàng

Chạy mỗi khi có đơn từ bất kỳ kênh nào. Mục tiêu: 0 giây chạm tay người.

WF-2 · Tiền về & đối soát

Chạy mỗi khi ngân hàng báo có. Khớp được thì tự ghi sổ; lệch mới gọi người.

WF-3 · Tồn kho → đặt hàng OEM

Chạy mỗi sáng. AI đề xuất, giám đốc duyệt một chạm ngay trên Telegram.

WF-4 · Nội dung → tuân thủ → đăng

Luồng quan trọng nhất với ngành TPCN/mỹ phẩm: nội dung bị chặn tự quay lại sửa, chỉ nội dung đạt mới đến tay người duyệt.

WF-5 · Báo cáo sáng 07:00

Giám đốc đọc 5 phút mỗi sáng thay vì mở 5 phần mềm.

WF-6 · Vận đơn trục trặc (thất bại / hoàn)

Xử lý theo quy tắc, chỉ chuyển người khi khách không phản hồi.

Cách triển khai

  • Cài n8n tự host (miễn phí): Docker trên VPS nhỏ (~150–300 nghìn đ/tháng) — docker run -d -p 5678:5678 n8nio/n8n; thêm HTTPS qua reverse proxy trước khi nhận webhook thật.
  • Thứ tự dựng theo lộ trình 12 tuần: WF-5 báo cáo sáng trước (dễ nhất, thấy giá trị ngay) → WF-1, WF-2 trước khi launch → WF-6 khi có đơn thật → WF-3, WF-4 khi vận hành ổn định.
  • Mỗi workflow export ra file JSON và lưu vào repo (thư mục n8n/) — có lịch sử sửa đổi, hỏng thì import lại trong 1 phút.
  • Claude Code viết được JSON workflow để import thẳng vào n8n — mô tả luồng bằng tiếng Việt, nhận file import; 6 sơ đồ trên chính là đặc tả để sinh file.
  • Mọi node lỗi trỏ về một Error Workflow chung: ghi log + nhắn Telegram — khớp nguyên tắc "hệ thống tự giám sát" của phòng Công nghệ.
  • Node chờ duyệt (Telegram + Wait) chính là "hàng đợi duyệt trung tâm" trong sơ đồ dòng chảy — mọi workflow dùng chung một bot, một nhóm chat.
